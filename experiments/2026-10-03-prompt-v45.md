# Prompt v4.5 (2026-10-03): what the real 31B does wrong in our trajectories

Source: Kaggle kernel v10 (real 31B, llama.cpp on T4x2, swelite, prompt v4.3, 4.5 min), 33 holdout trajectories.
Fidelity caveats: thinking was effectively ON (swelite never sends `enable_thinking: false`; the model wrote ~4.8k
chars of thought per task), and the T4 subprocess sandbox had a broken environment (Pydantic 1.10 for FastAPI tasks;
24 of 33 tasks hit import errors). Our T4 sandbox also leaked scratch files into patches. So T4 scores (1-3/33) say
little about prompts. The rich trajectories, whose environment works, still show clear behaviour problems:

| behaviour | example | v4.5 change |
|---|---|---|
| assumes `src/` (our own example said `grep ... src`) | rich_3938, rich_4075: 2-4 calls on empty `src` greps; code lives in `rich/` | find the package dir in the task message's layout first; never assume `src/` |
| greps common words for terse PR-title issues | rich_4075 "empty with end": `grep -rn "end" rich` | turn nouns into the API they name; grep definitions and keyword arguments |
| ignores the analogy the issue gives | rich_3777 "TTY_INTERACTIVE ... adds to the new TTY_COMPATIBLE": found TTY_COMPATIBLE, then 15 calls elsewhere, never edited; gold edits console.py and diagnose.py exactly where TTY_COMPATIBLE lives | grep the existing feature first; add the new one everywhere the old one is handled |
| explores without editing | rich_3777: 20 calls, 0 edits | start editing by call 12 at the latest |
| reads large ranges | `sed -n '1721,1850p'` (130 lines) | 60-line cap (was 80) |
| issue text sent twice | system prompt embedded `{problem_description}`; the official task message already contains it | removed from the system prompt |
| inaccurate lines | "numeric tool arguments are rejected" (retracted finding); "300 s" command limit (config is 180) | removed / corrected |
